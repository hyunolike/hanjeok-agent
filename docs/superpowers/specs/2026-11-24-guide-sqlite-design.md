# Aura 없이 실행하는 안내 API

상태: 사용자가 2026-11-24 읽기 전용 SQLite 전환과 배포 진행을 승인했다.
기준: `4b7b09f`, 깨끗한 `feat/guide-512mb-runtime` 작업 브랜치에서 이어 간다.
기존 [512MB 설계](2026-11-23-guide-512mb-design.md)의 무료 배포 경로를 대체한다.

## 목적과 선택

Mac 잠금으로 Aura 접속 파일을 확보하지 못해 공개 배포가 막혔다. 이미 검증한
공개 관광 데이터와 벡터를 읽기 전용 파일로 배포해 별도 DB 인증 없이 응답한다.
Places/Policy 경계와 HTTP/SSE 계약, NVIDIA 모델, 원본 순위와 인용 검사를 유지한다.
기존 Neo4j 경로와 과거 평가를 보존하며 SQLite로 얻은 결과를 Neo4j 평가로 표시하지 않는다.

대안인 Aura 유지는 현재 접속 파일이 필요하다. 신규 외부 DB는 계정과 인증이 다시
필요하다. 사용자는 데이터 파일을 이미지에 넣는 SQLite 방식을 선택했다.
키워드 검색이나 녹화 답변으로 대체하지 않고 같은 벡터의 정확 코사인 검색을 사용한다.
Neo4j 근사 검색과 경계 순위가 달라질 수 있어 과거 품질 수치를 재사용하지 않는다.

## 요구사항과 수용 기준

- S1: 운영자 빌더는 검증한 export와 기존 장소 캐시, 승인된 위키 캐시/manifest/
  promotion, clean 고정 위키 checkout만 읽는다. 캐시는 mode=ro로 열고 원문 청크의
  id/path/순서/해시까지 승인 manifest와 대조한다. 생성 중 모델/네트워크 호출은 하지 않는다.
  누락 벡터, 차원/유한수/정규화 오류, 다른 위키 원문/식별자는 생성 실패다.
- S2: SQLite 스키마와 메타데이터에 export 해시/시점/건수, 두 벡터 식별자,
  위키 revision/청크 수/producer/artifact 해시를 기록한다. 장소 12,106개,
  관계 43,087개, 행사 209개, 위키 18문서/83청크를 보존한다.
- S3: 빌더는 별도 임시 파일을 검증한 뒤 출력한다. 압축 DB와 JSON manifest를
  `bench/data/`에 둔다. 공개 allowlist 데이터만 포함하며 키/계정/개인 자료는 없다.
  gzip은 content-addressed 이름으로 먼저 쓰고 manifest만 원자적으로 마지막에 공개한다.
  Docker 빌드에서 압축/원본 SHA256을 확인하고 해제한다. 빌더 실패 시 기존 manifest와
  그것이 가리키는 gzip은 보존한다. 실패 중 생긴 미참조 gzip은 서빙하지 않는다.
- S4: 런타임은 mode=ro로 열고 확장 로드를 즉시 끈다. sqlite-vec의 C 코사인 함수를
  사용하고 전체 Python float 행렬은 만들지 않는다. 페이지 캐시 8MiB, mmap=0,
  연결 하나와 Lock으로 접근한다. 임베딩 HTTP 대기 중 DB 잠금을 잡지 않는다.
- S5: 이름 우선순위, 지역 사전 필터, 관계 rank/null/score/id 정렬, 행사 날짜와
  장소 직접 연결 또는 미연결 행사 1km 반경, 위키 상위 limit*3 청크 내 페이지 중복 제거와
  PAGE_CHARS를 유지한다. 동률은 id/path로 정렬한다. 모델이 SQL을 만들지 않는다.
- S6: `GUIDE_STORE=sqlite`와 명시한 DB/manifest를 사용한다. 없거나 손상/다른 스키마,
  다른 식별자/불완전 코퍼스면 준비되지 않음이며 Neo4j나 다른 데이터로 폴백하지 않는다.
  기존 기본 Neo4j 모드는 유지한다. /guide/ready는 NVIDIA 가용성을 대신하지 않는다.
- S7: 무료 배포 프로필은 SQLite를 선택하고 Aura 시크릿을 요구하지 않는다.
  NVIDIA 키만 기존 Render 시크릿으로 전달한다. 원격 ready/status와 실제 인용 SSE
  확인 후 Cloudflare 프론트 API URL을 빌드/공개한다. 비용 발생, main 병합은 하지 않는다.
- S8: 실제 전체 산출물과 HTTP 제공자/한적 API를 사용한 예보/정책/대안 응답을
  512MiB/no-swap, 단일 워커 제한에서 확인하고 이미지/메모리/OOM/한계를 기록한다.
  새 검색 결과를 과거 60문항 평가 점수로 표시하지 않는다.

## 검증과 범위

단위 테스트는 실제 SQLite 파일로 순위, 검색 필터, 행사 범위, 페이지 중복 제거,
원문/벡터 누락과 잘못된 식별자, 읽기 전용, 손상/누락 파일, API 준비 상태를 검증한다.
전체 기존 오프라인 suite와 Ruff를 실행한다. 새 문맥의 설계/최종 코드 검토를 별도로
실행하고 기록한다. 전체 EGM 수렴을 실행하지 않았으면 완료라고 주장하지 않는다.
기존 품질 문제(q37 정책 의도, q39/q40 범위, 내부 인용 ID)는 이번 저장소 교체에서
수정하지 않는다. 갱신은 운영자가 새 파일을 생성해 재배포하며 실행 중 핫스왑하지 않는다.
