# 한적 에이전트 연결 대기 경험

승인: 2026-11-24 사용자가 추천한 자동 깨우기, 질문 작성, 잎새 카드 뒤집기 구현을 승인했다.
기준: 87e445a, 작업 시작 시 변경 없음. 기존 질문/인용/검증 계약은 유지한다.

## 문제와 범위

Render 무료 API가 잠든 동안 질문 전송부터 답변 제한 시간까지 함께 소모하고,
빈 로딩 화면과 고정 30초 안내만 보여 준다. Cloudflare에서 먼저 열리는 질문 화면에서
연결을 준비하고, 질문을 적거나 선택형 카드를 넘길 수 있게 한다.
실제 기동 시간 단축, 상시 keepalive, 모델 가용성 보장, 완성형 게임은 범위 밖이다.
기존 선택 장소의 서버 측 검증 계약과 녹화본 예시 즉시 실행 동작은 보존한다.

## 요구사항과 수용 기준

- W1: 질문 화면 마운트 시 GET /guide/ready를 시작한다. 미제출 초안은 전송하지 않는다.
  활성 확인은 하나만 유지한다. 녹화 모드는 네트워크 확인 없이 기존 동작을 유지한다.
- W2: 준비 전에도 질문과 예시를 작성할 수 있다. 실서버 예시는 초안만 채운다.
  제출하면 질문을 화면에 보존하고 준비 완료 뒤 POST /guide/ask를 정확히 한 번 보낸다.
  제출 중 연타를 막고, 선택 장소/후속 방문/후보 선택 정보도 그대로 전달한다.
- W3: 매 제출마다 준비 상태를 재확인해 오래 열린 화면에서도 같은 경로로 복구한다.
  연결 대기 예산 90초와 기존 답변 스트림 예산 90초를 분리한다. 각 GET은 최대 12초,
  실패 후 5초 간격이며 무한 자동 재시도나 중첩 요청을 만들지 않는다.
- W4: HTTP 성공과 JSON ready:true를 모두 확인한다. 오류/잘못된 본문/503/네트워크
  실패는 예산 안에서 재확인한다. 준비 실패 시 질문은 남고 다시 연결/대기 취소가 가능하다.
  연결 재시도는 질문 POST 재전송이 아니다. 취소/언마운트 후 늦은 성공은 질문을 보내지 않는다.
- W5: 연결 준비 중에는 기존 잎새 looking 포즈와 정확한 상태 문구, 선택형 카드 뒤집기를
  보여 준다. 질문 전송 전 카드와 질문 예시를 구별한다. 카드 내용은 정적 사용 팁이며
  실시간 혼잡/추천 응답이 아니다. 준비 완료는 데이터 연결 준비만 뜻하고 AI 성공 보장이 아니다.
- W6: 연결 뒤에는 기존 실제 SSE 단계만 보여 준다. 임의 진행률/카운트다운/로딩 단계는
  없다. 고정 30초 안내를 삭제한다. 카드 참여 없이 전송 가능하며 포커스를 빼앗지 않는다.
  키보드 버튼, aria-expanded, polite 상태 안내, 기존 reduced-motion과 한/영 문구를 유지한다.

## 설계와 대안

`waitForGuideReady`는 종료 가능한 GET 확인을 담당한다. `useGuideConnection`은 화면별
활성 Promise를 공유하고 연결 상태를 관리한다. AskGuide는 제출된 요청 하나를 별도 큐에
보관하고 ready 결과가 참일 때 기존 submit의 SSE 부분을 실행한다. 취소 시 요청 식별을
무효화하여 새 요청에 옛 확인 결과가 적용되지 않게 한다. 실패 시 자동 POST 재전송은 없다.
카드는 기존 색/모양 토큰과 잎새 자산을 재사용하며 CSS 3D 회전이나 새 이미지가 필요 없다.
연결 대기 안내는 준비 완료 문구로 바꾸며 카드 조작은 유지해 포커스를 보존한다.
카드 버튼을 누르면 텍스트를 바꿔 공개하고 실제 SSE 진행은 기존 단계 영역에서 보여 준다.

대안: 스켈레톤만 유지하면 긴 대기에 할 일이 없다. 전체 미니게임은 모바일 조작/접근성
구현 비용이 커 이번 범위에서 제외한다. 주기적인 서버 깨우기는 방문자가 없을 때도
요청을 발생시켜 제외한다. 연결 상태를 최초 한 번만 확인하면 장시간 탭에서 재차 잠든
서버에 POST를 보내므로 제출 시 재확인을 선택했다.

## 위험과 검증 계획

외부 Render/NVIDIA 장애는 남는다. /guide/ready는 저장소 준비이며 NVIDIA를 호출하지
않는다. 실제 기동 시간은 측정하지 않았으므로 제품에 예상 시간을 표시하지 않는다.
여러 방문자/탭의 GET은 공유하지 않지만 한 화면의 확인은 순차이며 유한하다.
브라우저 재시도는 읽기만 수행하고 새로운 시크릿/저장소/모델 비용을 추가하지 않는다.

1. HTTP 단위 테스트: replay 무요청, ready 본문 확인, 503 복구, 예산 만료, 취소,
   진행 중 요청 정리와 네트워크 실패를 fake timer/실제 Response로 확인한다.
2. 화면 테스트: 마운트 확인, 입력 가능, 예시 초안, 제출 큐, 연타 방지, 재시도/취소,
   언마운트 뒤 성공 차단, 연결 후 SSE 전환, 카드 키보드 조작/언어를 확인한다.
3. 전체 frontend vitest와 typecheck, Cloudflare Pages 빌드를 실행한다.
4. 로컬 브라우저에서 지연 ready 응답으로 모바일/데스크톱 대기와 실제 SSE 전환을 확인한다.
   초기 구현은 로컬 검증까지였으며, 이후 사용자가 공개 배포 진행을 승인했다.

## 공개 배포 승인

구현 완료 보고 뒤 사용자의 “진행해줘” 요청으로 기존 Cloudflare Pages 운영 배포와
공개 브라우저 검증을 진행한다. 백엔드 구성이나 과금, Git main 병합은 변경하지 않는다.
