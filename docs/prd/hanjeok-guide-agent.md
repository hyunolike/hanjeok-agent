# PRD: 한적 에이전트

작성일 2026-10-14. 기준 명세는 [`specs/002-hanjeok-guide-agent/spec.md`](../../specs/002-hanjeok-guide-agent/spec.md)이고, 이 문서는 그 명세를 제품 관점에서 다시 쓴 것이다. 둘이 어긋나면 명세가 맞다.

## 1. 한 줄 설명

여행자가 "이번 토요일 경복궁 대신 조용한 곳 있어?"라고 물으면, 한적 서비스의 데이터와 정책 문서를 단계별로 찾아보고 근거를 붙여 답하는 안내 에이전트다.

## 2. 왜 만드는가

이 저장소는 지금까지 한 가지만 설명했다. 백엔드가 이미 만든 코스 하나를, 그 코스가 보이는 화면에서 설명하는 일이다. 코스에 없는 장소는 물을 수 없었고, 모델이 조회할 수 있는 것도 화면에 나온 장소의 혼잡도와 대안 두 가지뿐이었다.

검색 벤치를 만들면서 두 가지를 알게 됐다.

- 벡터 검색과 그래프 확장을 만들어 측정했지만 대상이 문서 14개였다. 고를 것이 거의 없는 크기라 검색이 하는 일이 드러나지 않았다.
- 검색이 실제로 일할 데이터는 옆에 있었다. 한적은 혼잡 예보가 있는 장소 약 1만 곳과 장소 사이의 연관 순위, 날짜별 혼잡 예보, 축제와 전시를 갖고 있다.

"경복궁과 분위기가 비슷하면서 이번 토요일에 한적한 곳"은 글이 비슷한 장소를 찾는 것만으로는 답할 수 없다. 연관 링크를 따라간 다음 날짜를 확인해야 한다. 이 프로젝트는 그런 질문을 받을 수 있게 하되, 저장소가 지켜 온 경계는 그대로 둔다. 어느 장소가 좋은 대안인지는 한적 백엔드가 정하고, 모델은 순위에 관여하지 않는다.

## 3. 누가 쓰는가

| 사용자 | 하려는 일 |
| --- | --- |
| 여행자 | 장소와 날짜를 넣어 묻고, 붐비는지와 대신 갈 곳을 안다 |
| 과제 평가자 | 데모 주소를 열어 질문 하나를 해 보고, 답의 경로와 평가 보고서를 5분 안에 찾는다 |
| 작성자 본인 | 두 검색 방식의 차이를 숫자로 확인하고, 데이터를 갱신한다 |

## 4. 무엇을 하는가

### 4.1 질문하고 근거 있는 답 받기 (P1)

질문을 치면 에이전트가 어떤 장소와 날짜를 말하는지 읽고, 혼잡 예보를 조회하고, 한적이 정한 대안을 받아 한국어로 답한다. 진행되는 단계가 하나씩 화면에 나온다.

- 답의 사실마다 근거가 붙는다. 장소나 날짜에 대한 사실은 한적 레코드를, 한적이 그 사실을 어떻게 다루는지는 정책 문서를 가리키고 화면에서 둘이 다르게 보인다.
- 이번 질문에서 실제로 조회한 것만 인용할 수 있다. 검증을 통과하지 못한 답은 한 글자도 화면에 나오지 않는다.
- 같은 이름의 장소가 둘이면 어느 곳인지 되묻는다.
- 한적이 예보하지 않는 장소는 "데이터 없음"이라고 답하고 한적하다고 말하지 않는다.
- 입장료와 영업시간처럼 갖고 있지 않은 정보는 답하지 않는다. 순위를 바꿔 달라는 요청도 거절한다.

### 4.2 답이 지나온 경로 보기 (P2)

답 아래에서 이 답이 거친 장소와 정책 문서, 그 사이의 관계를 그림과 목록으로 본다. 장소의 순서는 한적이 준 순위 그대로다. 질문 없이 장소 이름으로 찾아 이웃을 둘러볼 수도 있다.

### 4.3 평가 보고서 읽기 (P2)

준비한 질문 묶음을 두 가지 검색 방식으로 풀게 하고 채점한 결과를 누구나 볼 수 있다.

- 방식은 둘이다. 글 유사도만 쓰는 방식과, 거기서 연관 링크를 한 걸음 더 따라가는 방식이다. 질문과 지시문, 모델 설정, 판정 방법은 같고 모델에게 건넨 근거만 다르다.
- 모든 숫자 옆에 몇 문항으로 계산했는지 적는다. 채점하지 못한 문항은 0이 아니라 "채점 못 함"으로 적는다.
- 금지 행동 여섯 가지를 규칙으로 센다. 없는 장소를 지어냄, 한적의 순서를 바꿈, 모델이 골랐다고 말함, 근거 없는 주장, 등급 표기 오류, "데이터 없음"을 "한적함"으로 말함이다.

### 4.4 데이터 갱신하기 (P3)

한적 쪽에서 내보낸 파일로 에이전트의 사본을 통째로 바꾼다. 갱신이 중간에 실패하면 이전 사본이 그대로 남는다.

## 5. 성공 기준

| 기준 | 목표 |
| --- | --- |
| 첫 단계가 보이는 시간 | 3초 이내 |
| 답이 끝나는 시간 | 질문 묶음의 90% 이상에서 60초 이내 |
| 조회하지 않은 것을 인용한 답 | 0건 |
| 없는 장소를 말하거나 순서를 바꾼 답 | 0건 |
| 답하면 안 되는 질문의 거절률 | 90% 이상, 분모와 함께 공개 |
| 질문 묶음 | 60문항 이상, 여섯 종류마다 8문항 이상 |
| 두 방식의 차이 | 연관 장소 질문에서 필요한 레코드를 가져왔는지를 문항 수와 함께 공개. 어느 쪽이 이겨야 한다는 기준은 두지 않는다 |
| 처음 보는 평가자 | 질문, 경로 보기, 평가 보고서 찾기를 5분 안에 |
| 개인정보 | 에이전트의 사본에 0건. 갱신마다 받아들인 목록으로 확인 |

## 6. 하지 않는 것

- 한적 제품 화면 안에 넣는 일. 이번에는 별도 데모이고 한적 데이터를 읽기만 한다.
- 장소를 고르거나 점수를 매기거나 순위를 정하는 일.
- 예약, 결제, 길 찾기, 영업시간, 요금.
- 계정, 대화 저장, 개인화.
- 회원이 만든 콘텐츠(사진, 후기, 체감 혼잡 응답).

## 7. 데이터와 경계

- 한적 데이터는 한적 쪽에서 내보낸 파일로만 들어온다. 이 저장소는 한적 데이터베이스의 접속 정보를 갖지 않는다.
- 받는 것은 공개 관광 데이터뿐이다. 장소, 연관 관계, 축제, 전시이고 컬럼은 허용 목록으로 정해져 있다. 목록에 없는 컬럼이 파일에 있으면 읽기를 멈춘다.
- 혼잡 예보와 대안은 날짜에 묶인 값이라 질문이 들어올 때 한적 API 두 개로 조회한다. 조회수를 기록하는 장소 상세 API는 부르지 않는다.
- 모델은 쿼리를 쓰지 않는다. 정해진 조회 일곱 가지 중에서 고르고, 입력은 코드가 검증한다.

## 8. 기술 구성

| 영역 | 사용한 것 |
| --- | --- |
| 서비스 | Python 3.13, FastAPI, LangGraph(스트리밍, `interrupt`, 체크포인터), LangChain |
| 그래프와 검색 | Neo4j 5.26, neo4j-graphrag의 `VectorCypherRetriever`, 장소 벡터 인덱스(multilingual-e5-large, 1024차원), 연관 관계 `RELATED_TO` |
| 다른 프로그램과의 연결 | MCP 서버(읽기 전용 도구 네 개). 나중에 한적 백엔드가 이 입구로 호출 |
| 추적 | Langfuse. 키를 넣었을 때만 켜짐 |
| 정책 문서 | Obsidian 볼트로 관리하는 위키를 그래프에 적재 |
| 모델 | NVIDIA NIM의 nemotron, 구조화 출력 |
| 평가 | RAGAS 4개 지표, 레코드 id 기준 정밀도와 재현율, 규칙 기반 금지 행동 건수 |
| 화면 | Next.js 16, React 19, Tailwind 4 |
| 배포 | 서비스는 Docker로 Hugging Face Spaces, 화면은 Vercel |

## 9. 지금 상태 (2026-10-14)

- 화면 네 개와 서비스, 평가 실행기까지 만들었고 테스트가 통과한다.
- 호스팅 모델로 실제 답이 나오는 것을 확인했다.
- 데이터는 지어낸 장소 40곳으로 만든 가상 내보내기 파일이다. 한적의 실제 데이터로는 아직 돌리지 않았다.
- 배포하지 않았다.

## 10. 남은 위험

- **모델 제공자의 요청 한도**: 다른 프로젝트와 같은 키를 쓴다. 첫 평가 실행에서 24건 중 10건이 한도 때문에 실패했다. 평가는 한도를 기다리도록 바꿨지만, 방문자의 질문은 60초 안에 풀리지 않으면 실패한다.
- **판정 모델과 답하는 모델이 같다**: 판정 점수만으로는 주장할 수 없어서, 모델 없이 세는 지표를 함께 낸다.
- **Hugging Face Spaces에서 Neo4j와 임베딩 모델을 한 컨테이너에 올릴 수 있는지** 확인하지 않았다. 안 되면 호스팅 Neo4j로 바꾼다.
- **캐릭터 자산의 권리 검토**를 하지 않은 채 공개했다. 기록은 `design/guide-character/v1/provenance.json`에 있다.
